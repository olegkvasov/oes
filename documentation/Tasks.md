# Тестовое задание: экран диспетчера

К вакансии [Frontend Lead — интерфейс диспетчерской](vacancy.md). Объём — один рабочий день с ИИ-инструментами, 6–8 часов. Срок — 5 дней. Разбор на интервью — 90 минут.

## Задача

Система сама направляет машины к пунктам погрузки. В каждом решении — какую машину, куда, почему и какой выигрыш. Диспетчер не утверждает каждое решение, а следит за системой и вмешивается: отменяет решение до исполнения или переводит пункт в ручной режим. Экран открыт всю смену.

Сделайте экран на Vue 3 и TypeScript, заглушку сервера и проверки. Код пишите с ИИ-агентом — объём на это рассчитан. От вас — архитектура, проверки и ответственность за результат.

## Как мы проверяем

1. Запускаем команды из README на чистом клоне.
2. Запускаем экран на вашей и на своей заглушке с отказами сети и сравниваем экран с состоянием сервера.
3. Вносим в код нарушение каждого из правил 1–3 части 3 — `make check` должен поймать каждое.
4. На разборе вы меняете решение вместе со своим агентом; наш агент выполняет задачу по вашему `AGENTS.md`.

## 1. Заглушка сервера

`make mock` запускает заглушку на Node или Python по контракту ниже: 150 машин ездят между 6 пунктами, решения — раз в 5–15 секунд, исполнение — через 60 секунд после создания. Движение и решения простые, их правдоподобие не оцениваем.

| Параметр окружения | Что делает |
|---|---|
| `LOAD=1000` | 1 000 машин, каждая обновляется раз в секунду |
| `FAULTS=drop,dup,reorder` | Пропускает, повторяет, переставляет сообщения WebSocket |
| `FAULTS=reset` | Раз в 2 минуты рвёт соединение и отвечает `reset` на переподключение |
| `FAULTS=slow` | Задержка HTTP 3 секунды; часть команд выполняется на сервере, но клиент получает таймаут |
| `FAULTS=stale` | Часть машин перестаёт обновляться |
| `ROLE=observer` | `/api/me` возвращает наблюдателя, команды — 403 |
| `GET /debug/state` | Истинное состояние сервера и число выполнений каждой команды по `Idempotency-Key` |

### Контракт

Время — ISO 8601 в UTC. Координаты — метры в локальной системе площадки размером примерно 6 × 4 км.

| Запрос | Ответ |
|---|---|
| `GET /api/me` | `{"user_id": "u-7", "name": "Иванова А. С.", "role": "dispatcher", "site": {"name": "Площадка 3", "tz": "Asia/Krasnoyarsk"}}`; `role` — `dispatcher` или `observer` |
| `GET /api/snapshot` | `{"seq": 50412, "at": "…", "vehicles": [...], "points": [...], "decisions": [...]}` — состояние на момент `seq`; решения — за последний час |
| `POST /api/decisions/{id}/cancel` | Заголовки `Idempotency-Key` и `If-Match: <version>`. 200 — решение с новым статусом; 409 — уже исполнено, истекло или версия устарела, в теле — актуальное решение; 403 — нет прав |
| `POST /api/points/{id}/mode` | Тело `{"mode": "manual"}`, заголовки и ответы — как у отмены |
| WebSocket `/ws?since=<seq>` | Сообщения после `since`: `{"seq": 50413, "at": "…", "type": "vehicle" \| "point" \| "decision", "data": {…}}`, в `data` — полный объект после изменения. `seq` растёт на 1. Если сообщений после `since` уже нет — `{"type": "reset"}`, клиент заново запрашивает снимок. Раз в 5 секунд — `{"type": "heartbeat", "seq": …, "at": "…"}`, `at` — время сервера |

Повтор команды с тем же `Idempotency-Key` возвращает тот же ответ и не выполняет её второй раз.

```json
{"vehicle_id": "v-17", "name": "Т-17", "x_m": 2410.5, "y_m": 1180.0, "heading_deg": 72, "speed_kmh": 24.5,
 "state": "moving_empty", "point_id": "p-2", "last_seen": "2026-10-01T04:12:09Z"}

{"point_id": "p-2", "name": "Пункт 2", "x_m": 3120, "y_m": 900, "mode": "auto", "version": 14,
 "queue": [{"vehicle_id": "v-09", "eta": "2026-10-01T04:13:40Z", "service_start": "2026-10-01T04:15:10Z", "wait_s": 90}]}

{"decision_id": "d-3381", "vehicle_id": "v-17", "from_point": "p-2", "to_point": "p-4", "gain_s": 140,
 "reason": "Очередь на Пункт 2 — 4 машины, Пункт 4 свободен", "status": "pending",
 "created_at": "2026-10-01T04:12:05Z", "execute_at": "2026-10-01T04:13:05Z", "version": 1}
```

| Поле | Значение |
|---|---|
| `state` | `moving_loaded`, `moving_empty`, `queued`, `service`, `idle`, `offline` |
| `last_seen` | Последние данные от машины |
| `status` | `pending` → `executed`, `cancelled` или `expired` |
| `reason` | Текст для человека, может содержать любые символы |
| `version` | Растёт при каждом изменении, передаётся в `If-Match` |

## 2. Экран

1. **Схема площадки**: пункты и машины в реальном времени, цвет — по состоянию, устаревшие машины видны.
2. **Очереди**: по каждому пункту — машины, расчётный приезд, ожидание.
3. **Лента решений**: новые сверху; у ожидающих — обратный отсчёт до `execute_at` и кнопка «Отменить».
4. **Режим пункта**: авто или ручной, переключатель.
5. **Связь**: подключено, переподключение, данные устарели.

| № | Требование | Проверка |
|---|---|---|
| 1 | Показатели — очередь, ожидание, выигрыш — приходят с сервера, экран их не считает | чтение кода |
| 2 | Пропуск, повтор, перестановка сообщений и `reset` не приводят к расхождению с сервером | e2e: `FAULTS=drop,dup,reorder` 5 минут; `FAULTS=reset` |
| 3 | Команда выполняется на сервере один раз, в том числе при повторе после сбоя сети | e2e: `FAULTS=slow` — отмена с таймаутом и повтором, по `/debug/state` одно выполнение |
| 4 | На экране — состояние из ответа сервера. Конфликт — понятное сообщение и актуальное состояние | e2e: отмена решения, которое сервер уже исполнил, — 409, сообщение, статус `executed` |
| 5 | Наблюдатель не видит кнопок действий; ответ 403 обработан | e2e: `ROLE=observer` — кнопок нет; команда в обход интерфейса — сообщение об отказе |
| 6 | Машина без данных дольше 30 секунд по времени сервера показана устаревшей | e2e: `FAULTS=stale` |
| 7 | Время — в часовом поясе площадки из `/api/me`, не браузера | `make test` |
| 8 | Нет запросов к внешним адресам: шрифты, иконки и подложка — в сборке | открываем экран без интернета |
| 9 | 12 часов работы без роста памяти и подтормаживаний | `make perf` |

## 3. Правила кода

1. Код разложен по модулям `src/modules/<module>/`. Импорт между модулями — только через `index.ts` модуля-владельца. Циклов нет.
2. Контейнер (`*Container.vue`) отвечает за запросы, состояние и ошибки. Компонент показывает данные из props и сообщает о действиях через emit; запросов не делает, store не меняет.
3. HTTP — только в слое `api` модуля через один общий клиент. Бизнес-функции — в `helpers`, технические — в `utils`.
4. Pinia — только для общего долгоживущего состояния. Функция, меняющая состояние store, называется с суффиксом `Mutator`.

`make check` проверяет правила 1–3 автоматически, вместе с типами `vue-tsc` и линтером. Нарушение — ошибка, а не предупреждение.

## 4. Тесты

1. `make test` — Vitest: порядок и пропуски `seq`, переход на снимок, состояние команды, время в поясе площадки.
2. `make e2e` — Playwright на заглушке: все сценарии из колонки «Проверка» части 2. После каждого сценария состояние на экране совпадает с `/debug/state`.

## 5. Производительность

`make perf`: Playwright открывает экран на заглушке с `LOAD=1000` на 10 минут и пишет в `perf/report.md`:

| Метрика | Цель |
|---|---|
| Long tasks дольше 50 мс, по минутам | не больше одного в минуту |
| Кадров в секунду на схеме: среднее и 5-й перцентиль | не меньше 30 |
| JS heap после прогрева и в конце | рост не больше 10 % |

`PLAN.md`. Вы — Frontend Lead, в команде один middle-разработчик, оба работаете с ИИ-агентами. Сейчас есть 5 старых приложений на Vue 2 и React, около 30 экранов, документации к ним почти нет. Через 10 недель экран диспетчера должен работать на первой площадке, а старые экраны диспетчера — быть выключены.

1. 8–12 задач: результат, критерий приёмки, зависимости, исполнитель — вы, middle или агент.
2. Как извлечь поведение старых экранов без документации: что поручаете агенту и как проверяете, что ничего не потеряли.
3. Что должно быть готово к концу второй недели.
4. Правила работы с агентами для команды: что поручать, что обязательно проверять, как ревьюить MR агента.
5. Три главных риска и первое действие по каждому.
6. Что не делаете до запуска.

## Если не успеваете

`AGENTS.md` и `PLAN.md` обязательны. Дальше по порядку: слой API и поток со снимком и `seq` → лента решений и команды → схема с `LOAD=1000` → `make check` → e2e → `make perf` → остальное. Что не успели — перечислите в README.
