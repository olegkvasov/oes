# Работа в репозитории

Источник требований — Tasks.md. Интерфейс на русском, схема на Canvas в локальных метрах.
Модули находятся в src/modules. Межмодульные импорты только через index.ts владельца; циклы запрещены.
Контейнеры \*Container.vue владеют запросами, состоянием и ошибками. Компоненты принимают props и испускают emit; не выполняют запросы и не меняют store.
HTTP только в api модуля через transport. Бизнес-логика в helpers, технические функции в utils. Изменения Pinia store именуются с суффиксом Mutator.
Не рассчитывать серверные показатели на клиенте. Не вставлять reason как HTML. Не добавлять внешние шрифты, подложки и CDN.
При повторе неизвестного результата команды сохранять Idempotency-Key, тело и If-Match. Ответ 409 должен обновить объект.
Команды: yarn install, make mock, make dev, make check, make test, make build. Типы проверяет vue-tsc; тесты потока — tests/unit/synchronization.test.ts, контракта — tests/unit/server.test.ts, архитектурных нарушений — tests/unit/architecture.test.ts. E2E запускается make e2e (сам поднимает серверы); производительность — make perf. Не запускать их параллельно: используют одни порты.
Важно: базовые проверки реализованы в scripts/check-architecture.mjs; ESLint настроен в eslint.config.mjs; полное покрытие архитектурных правил пока не реализовано. Не считать make check полной проверкой требований.
Перед отчётом запускать проверки и точно указывать непроверенные сценарии. Не выдумывать результаты производительности и ошибки, якобы найденные человеком.

ESLint и Prettier: `yarn lint`, `yarn lint:fix`, `yarn format`, `yarn format:check`. `make check` включает типы, ESLint без допустимых предупреждений, архитектуру и форматирование. Перед сдачей изменения форматировать Prettier; не отключать правила ради прохождения проверки. Tasks.md и генерируемый documentation/performance/report.md исключены из форматирования.

Менеджер пакетов — Yarn Classic 1.22.22. Использовать только yarn.lock; не создавать package-lock.json. Установка в CI: `yarn install --frozen-lockfile`.

Тестовые endpoints включаются только TEST_CONTROL=1; состояние рендера доступно тестам только VITE_E2E=1, счётчик Canvas — VITE_PERF=1. Не включать эти флаги в production. При изменении команд проверять tests/unit/command.test.ts, при изменении симуляции tests/unit/mock-behavior.test.ts. После сетевой ошибки никогда не создавать новый Idempotency-Key для повтора того же намерения.

## Размещение файлов — обязательное правило

- Вся содержательная документация, задания, планы и Markdown-отчёты находятся в `documentation/`. Корневые `README.md` и `AGENTS.md` служат только точками входа и ссылками.
- Модульные и интеграционные тесты — `tests/unit/`, браузерные — `tests/e2e/`, нагрузочные — `tests/performance/`.
- Конфигурации Vitest/Playwright и тестовые runners также находятся в `tests/`. Общие проверки кода — в `scripts/`.
- Генерируемые браузерные артефакты — `tests/.artifacts/` (не сохранять в репозитории); отчёт производительности — `documentation/performance/report.md`.
- Не создавать корневые `e2e/`, `perf/`, отдельные Markdown-документы или тесты рядом с исходным кодом. При перемещении обновлять импорты, конфигурации, Makefile и ссылки.
- Правило проверяет `node scripts/check-layout.mjs`, включённый в `make check`.

Расположение документов и отчёта отличается от исходного Tasks.md по последующему явному указанию пользователя собрать документацию в documentation, а тесты — в tests. Команды make сохранены.
